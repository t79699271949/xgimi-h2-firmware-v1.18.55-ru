# Грабли этого образа

Каждый пункт — реальная ошибка, которая стоила часов или почти убила проектор. Порядок — от самых
опасных.

## 1. Загрузчик — не трогать

Экран меню обновления (лупа, стрелка вверх, китайские подписи) рисует **MStar LK (bootloader)**.
Он не входит в `system.img`, откатить его нечем. Правишь — получаешь кирпич без UART.

**Китайские надписи в меню обновления остаются осознанно.** Это единственное место, где они есть.

## 2. `e2fsck -fy` портит образ

Запуск `e2fsck -fy` на этом образе ломает файловую систему (проверено). Для инспекции — только
`debugfs -R "..."`, для записи — `debugfs -w -R "..."`.

## 3. Скрипты с CRLF молча не запускаются

Windows-редактор (и Python `open(path, "w")` на Windows) пишет `\r\n`. Шебанг становится
`#!/system/bin/sh\r`, система не находит интерпретатор и **тихо** пропускает скрипт.

Симптом: прошивка встала, система грузится, но **нет ADB, агента, чистки, Sogou-off**. Может
выглядеть как «завис на логотипе XG».

Проверка перед вшиванием:

```python
assert open(path, "rb").read().count(b"\r\n") == 0
```

## 4. `desc.txt` в анимациях — только LF

`shutdownanimation.zip` / `bootanimation.zip` с `\r\n` в `desc.txt` не проигрываются, вместо
анимации — чёрный экран. Собирайте zip на Linux/WSL или конвертируйте `desc.txt` в LF.

## 5. APK в `/system/app` не грузится

Проектор с APK, положенным в `/system/app`, **не загружается**. Приложения — только
`/system/etc/restore-apps/` + `pm install -r` хуком.

## 6. `debugfs rm -rf` не удаляет каталоги

`debugfs -R "rm -rf /path"` молча не срабатывает для каталогов. Удаляйте файлы по одному, затем
`rmdir`.

## 7. Лимит образа — 371 077 блоков

1 519 931 392 байт. Больше — загрузчик не примет, и вы узнаете об этом только после неудачной
прошивки.

## 8. Заголовок `.bin`

Только `mmc erase.p system` + `mmc unlzo`. Добавление `set_config` или
`recovery_wipe_partition data` ломает загрузку и стирает данные пользователя.

## 9. Overlay не работает для сторонних приложений

RRO (`/vendor/overlay/*.apk` с `targetPackage`) применяется к системным пакетам. К сторонним
(например Aerial) — нет. Для них берётся APK с готовым `values-ru`.

## 10. Несколько `%s` без позиционных в overlay

Если в строке несколько `%s` без `%1$s`, `aapt2` собирает overlay **пустым** — молча. Добавляйте
`formatted="false"` или позиционные аргументы.

## 11. `sdkmanager` падает на Windows

`heap corruption 0xC0000374`. Обход: скачать `platform-34-ext7_r03.zip` и
`build-tools_r34-windows.zip` напрямую с `dl.google.com` и распаковать вручную:
`android-34/` → `sdk/platforms/android-34/`, `android-14/` → `sdk/build-tools/34.0.0/`.

## 12. Java-классы, которых нет в Android 6

`java.nio.file.*` отсутствует на API 23, десугаринг его не покрывает — заменяйте на потоки
(`FileInputStream`/`FileOutputStream`). Для `java.util.function` нужен desugaring (второй dex).

## 13. `su` / `adb root` не работают

Root на устройстве недоступен: `su -c id` не даёт прав, `adb root` игнорируется. Поэтому правка
системных APK невозможна — только overlay.

## 14. `adb reboot` выключает проектор

На этой прошивке `adb reboot` не перезагружает, а выключает устройство. Перезагрузка — через меню
питания или кнопку.

## 15. Анимация выключения — только после правки

`shutdownanimation.zip` подхватывается не из `/system/media` напрямую, а из vendor-раздела. Если
анимация не поменялась — проверьте, куда именно попал файл, и что `desc.txt` валиден.
